## 애니메이션이 컴포지터로 넘어갔다

`PipelineReporter`의 `has_compositor_animation`이 681건 찍혔고 그중 679건이 전환 구간 안이며, `has_main_animation`은 트레이스 전체에 0건이다. 0.5초 보간을 메인 스레드가 전혀 건드리지 않는다.

| 항목               | 개선 전                    | 개선 후                                     |
| ------------------ | -------------------------- | ------------------------------------------- |
| `Animation` 이벤트 | —                          | 10전환 × `transform` + `opacity` = 20건     |
| 전환 구간 `Layout` | 57회                       | **0회**                                     |
| 전환 구간 `Paint`  | 109개                      | **시작 2개 + 종료 2개, 중간 500ms는 0개**   |
| `Paint` 클립       | 뷰포트 전폭 3456 device px | **무한 클립** (패널이 자기 레이어를 갖는다) |

트레이스에 `Layout`과 `LayoutShift`라는 이벤트 이름이 아예 없다. 패널이 `right` 대신 `transform`으로 움직이면서 레이아웃 박스가 바뀌지 않으므로, 개선 전에 매 프레임 662개 트리를 다시 돌던 `layoutRoots: #document` 레이아웃이 통째로 없어졌다.

`Recalculate Style` 15.5회도 매 프레임 도는 것이 아니다. 전환 하나를 뜯어보면 시작(+12~22ms)과 종료(+479~522ms)에 몰려 있고 중간에 흩어진 2~3건은 `pointermove` 히트 테스트가 부른 것이라, 건수는 늘어 보여도 소요는 18.6ms에서 3.45ms로 줄었다.

## 남은 `Paint` 4개와 partial 12건은 같은 원인이다

전환 1회에 남은 `Paint`는 시작에 2개(`#document`, `SECTION`), 종료에 2개로 전환당 4개이고, Partially Presented Frame 12건도 전부 시작 +11~36ms 또는 종료 −2~11ms에 걸쳐 있다. 보간이 도는 500ms 동안은 둘 다 0이다.

패널이 애니메이션 시작에 자기 레이어로 올라갔다가 끝나면 문서 레이어로 되돌아오는 왕복이 경계 20개 중 12개에서 컴포지터 프레임을 갈랐고, S3 개선 후 측정에서 `.gifItem`이 보인 것과 같은 형태다. 12건 전부 `frame_type: FORKED`이고 `affects_smoothness`가 `false`라 체감 끊김으로는 집계되지 않는다.

`will-change: transform`으로 패널을 상시 레이어에 올리면 왕복이 사라질 후보지만, 패널은 화면에 하나뿐이고 남은 비용이 전환당 6ms라 지금 상태로도 목표치를 넘겼다.

## Dropped Frame 20건은 GIF 재생분이다

전환 구간 dropped 20건 중 `affects_smoothness: true`는 6건이고, 6건 모두 `frame_type: BACKFILL`에 전환 시작 +198~427ms 구간이며 주변 20ms 안에 `Decode Image`가 1~3건씩 있다. 패널이 멈춰 있는 정지 구간에서도 6건이 나온다.

개선 전 0.5%에서 3.2%로 오른 것은 뷰포트가 좁아져 같은 화면에 GIF가 더 촘촘히 들어온 development 빌드 조건의 영향이며, 개선 전 문서가 정리한 대로 GIF 재생 부하이므로 TODO 1번 범위다.
